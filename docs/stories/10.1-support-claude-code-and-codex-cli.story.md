## Story

As a developer using Claude Code or Codex CLI,
I want to point my AI coding tool at `http://localhost:8080` as a drop-in proxy,
So that all my LLM calls are routed, load-balanced, and logged by MiniRouter without changing my tool's workflow.

## Acceptance Criteria

1. `x-api-key: <value>` header on `/v1/messages` or `/v1/chat/completions` is accepted and validated the same way as `Authorization: Bearer <value>`.
2. When `AUTH_PASSTHROUGH=true` env var is set, any key value (or no key) is accepted; `ctx.Items["ApiKeyId"]` is set to `"passthrough"`; a startup warning is logged.
3. When `AUTH_PASSTHROUGH=false` (default), unknown or missing keys are still rejected with 401 — existing behaviour is unchanged.
4. `anthropic-version` and `anthropic-beta` request headers are forwarded to upstream providers whose `BaseUrl` contains `api.anthropic.com`; they are stripped for all other providers.
5. `GET /v1/models` returns a valid OpenAI-format response `{ "object": "list", "data": [...] }` aggregating models from all enabled providers, deduplicated by model ID, with the same cache TTL as `/models`.
6. A model name sent without a `/` prefix (e.g. `gpt-4o`, `claude-opus-4-5`) routes correctly via the existing round-robin path — no 400 error.
7. `GET /api/config/auth-passthrough` returns `{ "enabled": true|false }` reflecting the current env var value; no auth filter applied.
8. The frontend has an "Integrations" tab with copy-paste shell commands for both Claude Code and Codex CLI, and a badge showing the current auth-passthrough state.
9. All new and existing backend tests pass; `dotnet build` is clean; `cd frontend && npm run build` is clean.

### Task 3 — Anthropic Header Forwarding (AC: 4)

**File:** `Services/ProxyService.cs` — method `HandleAnthropicMessagesAsync`

- [ ] 3.1 After the existing header-copy loop (~line 220), add explicit forwarding for `anthropic-version` and `anthropic-beta`:
  ```csharp
  // Forward Anthropic-specific headers only to Anthropic-native upstreams
  // (resolved later in ExecuteSingleProviderAsync — store in request headers now)
  foreach (var key in new[] { "anthropic-version", "anthropic-beta" })
  {
      if (ctx.Request.Headers.TryGetValue(key, out var val) && val.Count > 0)
          executionRequest.Headers[key] = val.ToArray();

  ```
- [ ] 3.2 In `ExecuteSingleProviderAsync` (the method that actually calls `HttpClient`), after building the outgoing `HttpRequestMessage`: if the provider's `BaseUrl` does **not** contain `"api.anthropic.com"`, remove `anthropic-version` and `anthropic-beta` from the outgoing headers before sending.
  ```csharp
  if (!provider.BaseUrl.Contains("api.anthropic.com", StringComparison.OrdinalIgnoreCase))
  {
      outgoingRequest.Headers.Remove("anthropic-version");
      outgoingRequest.Headers.Remove("anthropic-beta");
  }
  ```
- [ ] 3.3 Confirm the `ExecuteSingleProviderAsync` method copies `executionRequest.Headers` onto the outgoing `HttpRequestMessage` — verify this is already happening; if not, add the copy loop.

> **Dev Note:** `HandleAnthropicMessagesAsync` already has a header-copy loop at ~line 218 that strips `Authorization`, `Host`, `Transfer-Encoding`, `Content-Type`, `Content-Length` and forwards the rest. `anthropic-version` and `anthropic-beta` currently pass through this loop without problem — but are then silently forwarded to ALL upstreams. ### Task 4 — `GET /v1/models` OpenAI-Format Endpoint (AC: 5)

**File:** `Program.cs`

- [ ] 4.1 Add a new record DTO to `Models/Provider.cs`:
  ```csharp
  public record OpenAiModelEntry(string Id, string Object, string OwnedBy);
  public record OpenAiModelList(string Object, List<OpenAiModelEntry> Data);
  ```
  Register both in `AppJsonContext`:
  ```csharp
  [JsonSerializable(typeof(OpenAiModelEntry))]
  [JsonSerializable(typeof(OpenAiModelList))]
  [JsonSerializable(typeof(List<OpenAiModelEntry>))]
  ```

- [ ] 4.2 Add route in `Program.cs` (place it adjacent to the existing `/models` route):
  ```csharp
  app.MapGet("/v1/models", async (IProviderService providerService, IMemoryCache cache, IConfiguration config) =>
  {
      const string cacheKey = "v1_models_openai";
      if (cache.TryGetValue(cacheKey, out OpenAiModelList? cached) && cached != null)
          return Results.Json(cached, AppJsonContext.Default.OpenAiModelList);

      var providers = await providerService.ListProvidersUnmaskedAsync();
      var seen = new HashSet<string>(StringComparer.OrdinalIgnoreCase);
      var data = new List<OpenAiModelEntry>();

      foreach (var p in providers.Where(p => p.Enabled))
      {
          var models = p.Models ?? (p.Model != null ? new List<string> { p.Model } : new List<string>());
          foreach (var m in models)
          {
              var id = m.Contains('/') ? m : $"{p.Id}/{m}";
              if (seen.Add(id))
                  data.Add(new OpenAiModelEntry(id, "model", p.Id));
          }
      }

      int ttl = 300;
      if (int.TryParse(config["MODELS_CACHE_TTL_SECONDS"] ?? Environment.GetEnvironmentVariable("MODELS_CACHE_TTL_SECONDS"), out int parsed))
          ttl = parsed;

      var result = new OpenAiModelList("list", data);
      cache.Set(cacheKey, result, TimeSpan.FromSeconds(ttl));
      return Results.Json(result, AppJsonContext.Default.OpenAiModelList);
  });
  ```

> **Dev Note (AOT critical):** Every DTO used in `Results.Json(…, AppJsonContext.Default.X)` MUST be registered in `AppJsonContext`. Anonymous objects (`new { enabled = … }`) are NOT AOT-safe — use named records. [Source: docs/archive/system-architecture.md#Data Models — JsonContext]

## Dev Notes

### System Architecture Snapshot (relevant to this story)

**Auth filter** (`Filters/ApiKeyEndpointFilter.cs`):
- Checks `Authorization` header only. Local loopback + `ASPNETCORE_ENVIRONMENT=Development` bypass present.
- `IApiKeyService.ValidateAndRecordUsageAsync` does SHA-256 hash lookup → cache → SQLite.
- `IConfiguration` is NOT currently injected — Task 2 adds it.
[Source: docs/archive/system-architecture.md#Auth Filter]

**Proxy service routing** (`Services/ProxyService.cs`):
- `model` with `/` → explicit provider: `ExecuteCompletionAsync` splits on `/`, calls `GetProviderByIdUnmaskedAsync`.
- `model` without `/` → round-robin: `HandleRoundRobinExecutionAsync` → `GetNextProviderAsync(modelName, excludedIds)`.
- Header forwarding loop in `HandleAnthropicMessagesAsync` skips `Authorization`, `Host`, `Transfer-Encoding`, `Content-Type`, `Content-Length` but passes everything else — `anthropic-version`/`anthropic-beta` currently pass through to ALL upstreams.
[Source: Services/ProxyService.cs lines 218–225, 293–354]

**AOT serialization constraint:**
- `AppJsonContext` at `Models/Provider.cs` line 84 must register every DTO that crosses a wire boundary.
- Anonymous types (e.g. `new { enabled = true }`) are NOT AOT-safe. Always use named records.
- New types for this story: `OpenAiModelEntry`, `OpenAiModelList`, `AuthPassthroughConfig`.
[Source: docs/archive/system-architecture.md#Data Models — JsonContext]

**Existing models endpoint** (`/models` at `Program.cs` line 510):
- Calls upstream providers' `/v1/models`, caches the full `AggregatedModels` list.
- `GET /v1/models` (Task 4) should reuse the **provider's in-memory model list** (`provider.Models`, `provider.Model`) rather than making new upstream HTTP calls — avoids latency and rate-limit exposure.
[Source: Program.cs lines 510–570]

**Frontend nav** (`frontend/src/App.svelte`):
- Two nav groups: `operateTabs` and `observeTabs`.
- Tabs are `{ id, label, icon }` — icons from `@lucide/svelte`.
- `CliTool` is a useful reference for simple single-panel components with copy patterns.
[Source: frontend/src/App.svelte lines 1–50]

**No specific guidance found in architecture docs** for: Svelte 5 component test patterns (use existing `Presets.test.js` as reference), `WebApplicationFactory` usage (not established in this codebase — prefer unit tests over integration tests).
