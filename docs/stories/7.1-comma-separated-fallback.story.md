# Story 7.1: Comma-Separated Fallback Chains

## Description
To close the resiliency feature gap with 9Router while preserving MiniRouter's Native AOT micro-footprint, we are introducing **Comma-Separated Fallback Chains** directly in the standard request payload. 

By allowing the client to specify a comma-separated list of explicit models (e.g., `"model": "openai-primary/gpt-4o-mini, openai-secondary/gpt-4o-mini, anthropic/claude-3-haiku"`), we push the routing/fallback logic to the client side. `ProxyService` will parse this list, attempt the first model, and automatically fall back to the next model if:
1. The circuit breaker is open (`unhealthy` / `cooldown`) for the target model.
2. The upstream provider returns a 5xx error (500, 502, 503, 504).
3. The target provider is disabled or not found.

This avoids the need for complex database-backed proxy pool configurations while delivering the same high availability.

## Implementation Steps

### 1. Update `ProxyService.ExecuteCompletionAsync`
- Currently, the `ExecuteCompletionAsync` method splits the `RequestedModel` by `/` and assumes a single target.
- **Change**: Split `request.RequestedModel` by `,` (comma) first. 
- Create a fallback loop (`foreach (var target in targetModels)`):
  - Split each `target` by `/` to get `providerId` and `modelName`.
  - Check the provider state and the model's circuit breaker status.
  - If the circuit is open, or the provider is disabled/missing, record the failure result and `continue` to the next target model in the fallback chain.
  - If healthy, execute `ExecuteSingleProviderAsync`.
  - If the execution fails with a 5xx status code (e.g., 500, 502, 503, 504) or a timeout, record the result and `continue` to the next fallback.
  - If the execution succeeds or fails with a 4xx client error (e.g., 400 Bad Request, 401 Unauthorized, 422 Unprocessable Entity), immediately `return` the result to the client without falling back.

### 2. Preserve Round-Robin Behavior
- If the `request.RequestedModel` does NOT contain any `/`, it means it's a model name alias intended for the round-robin pool. Keep the existing branch that calls `HandleRoundRobinExecutionAsync`.

### 3. Handle Exhausted Fallbacks
- If the loop finishes and all specified fallback models failed or tripped circuits, return the `lastResult` or a generic `502 Bad Gateway - All fallback models exhausted`.

## Acceptance Criteria
- [x] Passing a single explicit model (`"providerX/modelA"`) works as before.
- [x] Passing a comma-separated list (`"providerX/modelA,providerY/modelB"`) successfully falls back to `providerY/modelB` if `providerX/modelA` returns a 503 or has an open circuit.
- [x] If `providerX/modelA` returns a 400 Bad Request, it does **not** fall back (because client errors shouldn't trigger retries).
- [x] If all models in the fallback chain fail, the router returns the error of the final model in the chain.
