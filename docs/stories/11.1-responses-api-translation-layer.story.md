# Story 11.1: Responses API Translation Layer (Codex CLI Support)

## Status

Draft

## Story

As a developer using Codex CLI (v0.122+),
I want to add MiniRouter as a custom model provider with `wire_api = "responses"` in `~/.codex/config.toml`,
So that all Codex LLM calls are routed through MiniRouter's load-balancing, circuit-breaking, and cost-logging infrastructure without any changes to the upstream providers.

## Acceptance Criteria

1. `POST /v1/responses` is registered and protected by `ApiKeyEndpointFilter` (same rules as `/v1/chat/completions`).
2. A string `input` field is converted to a single `user` role message.
3. An `input` array of `InputItem` objects (`type: "message"`) is converted to `messages[]` preserving `role` and `content`.
4. An `instructions` field is prepended as a `{"role":"system","content":"..."}` message.
5. `function_call_output` items in the `input` array are translated to `{"role":"tool",...}` messages.
6. Non-streaming (`stream: false`) response returns `{ "id": "...", "object": "response", "status": "completed", "output": [{"type":"message","role":"assistant","id":"...","status":"completed","content":[{"type":"output_text","text":"...","annotations":[]}]}], "usage": {"input_tokens": N, "output_tokens": N, "total_tokens": N} }`.
7. Streaming (`stream: true`) emits SSE events in order: `response.created` → `response.output_item.added` → `response.output_text.delta` (one per chunk) → `response.output_text.done` → `response.output_item.done` → `response.completed`.
8. Tool call outputs from the model (`type: "function_call"` in Chat Completions `choices[0].message.tool_calls`) are translated to `output[]` items with `type: "function_call"` in the Responses shape.
9. `previous_response_id` and `store` fields are accepted without error and silently ignored.
10. `max_output_tokens`, `temperature`, `tools`, `tool_choice` are forwarded as-is to the Chat Completions request.
11. `CliTool.svelte` Codex card chip updates to green "Supported" with a working `config.toml` snippet and no amber warning.
12. `Integrations.svelte` Codex section shows working `config.toml` instructions.
13. All new and existing tests pass; `dotnet build` clean; `cd frontend && npm run build` clean.

## Tasks / Subtasks

### Task 1 — `ResponsesRequestTranslator.cs` (AC: 2, 3, 4, 5, 10)

**File:** `Services/Translation/ResponsesRequestTranslator.cs` (new)

Build a `JsonNode`-based static translator. No typed DTOs for wire shapes (AOT constraint — mirrors `AnthropicRequestTranslator` pattern).

- [ ] 1.1 Create `public static class ResponsesRequestTranslator` with method `public static JsonObject ToOpenAI(JsonNode req)`.
- [ ] 1.2 Build `messages` `JsonArray`:
  - If `req["instructions"]` is a non-empty string, prepend `{"role":"system","content":"<value>"}`.
  - If `req["input"]` is a `JsonValue` string, append `{"role":"user","content":"<string>"}`.
  - If `req["input"]` is a `JsonArray`, iterate each `InputItem`:
    - `type == "message"`: map `role` and `content` to Chat Completions message. Content may be a string or an array of content parts — handle `type: "input_text"` parts by extracting `text`.
    - `type == "function_call_output"`: map to `{"role":"tool","tool_call_id":"<call_id>","content":"<output>"}`.
    - Other types: skip silently.
- [ ] 1.3 Build output `JsonObject`:
  ```json
  {
    "model": "<req.model>",
    "messages": [...],
    "stream": <req.stream ?? false>
  }
  ```
  Forward these fields if present: `max_output_tokens` → `max_tokens`, `temperature`, `tools` (as-is — same `function` schema), `tool_choice`.
- [ ] 1.4 When `stream == true`, add `"stream_options": {"include_usage": true}` (same as `AnthropicRequestTranslator`).

### Task 2 — `ResponsesResponseTranslator.cs` (AC: 6, 8)

**File:** `Services/Translation/ResponsesResponseTranslator.cs` (new)

Translate a non-streaming Chat Completions response `JsonNode` to Responses API shape.

- [ ] 2.1 Create `public static class ResponsesResponseTranslator` with method `public static JsonObject ToResponses(JsonNode resp, string model)`.
- [ ] 2.2 Build `output` array — one item of `type: "message"`:
  - `id`: generate `"msg_" + resp["id"]` (strip `chatcmpl-` prefix if present), or generate from timestamp.
  - `role`: `"assistant"`
  - `status`: `"completed"`
  - `content`: array with one item `{"type":"output_text","text":"<choices[0].message.content>","annotations":[]}`
- [ ] 2.3 If `choices[0].message.tool_calls` is non-empty, add additional output items with `type: "function_call"` for each tool call:
  ```json
  {
    "type": "function_call",
    "id": "<tc.id>",
    "call_id": "<tc.id>",
    "name": "<tc.function.name>",
    "arguments": "<tc.function.arguments>",
    "status": "completed"
  }
  ```
- [ ] 2.4 Build usage: `{ "input_tokens": usage.prompt_tokens, "output_tokens": usage.completion_tokens, "total_tokens": usage.total_tokens }`.
- [ ] 2.5 Return:
  ```json
  {
    "id": "<response-id>",
    "object": "response",
    "created_at": <unix-seconds>,
    "status": "completed",
    "model": "<model>",
    "output": [...],
    "usage": {...},
    "error": null,
    "incomplete_details": null
  }
  ```
- [ ] 2.6 Add `public static JsonObject BuildError(int statusCode, string message)` for error responses:
  ```json
  { "object": "response", "status": "failed", "error": { "code": "server_error", "message": "..." }, "output": [] }
  ```

### Task 3 — `ResponsesStreamTranslator.cs` (AC: 7, 8)

**File:** `Services/Translation/ResponsesStreamTranslator.cs` (new)

Translate Chat Completions SSE chunks to Responses API SSE event sequence. Mirrors `AnthropicStreamTranslator` pattern with a `ref ResponsesStreamState state` parameter.

- [ ] 3.1 Create `public class ResponsesStreamState` in `Models/Provider.cs`:
  ```csharp
  public class ResponsesStreamState
  {
      public bool ResponseCreatedSent { get; set; }
      public bool OutputItemAddedSent { get; set; }
      public string ResponseId { get; set; } = "";
      public string Model { get; set; } = "";
      public bool TextDeltaStarted { get; set; }
      public Dictionary<int, ToolCallInfo> ToolCalls { get; set; } = new();
      public int? UsageInputTokens { get; set; }
      public int? UsageOutputTokens { get; set; }
  }
  ```
  Reuse existing `ToolCallInfo` record from `Models/Provider.cs`.

- [ ] 3.2 Create `public static class ResponsesStreamTranslator` with method `public static List<(string EventName, JsonObject Data)> Translate(JsonNode chunk, ref ResponsesStreamState state)`.

- [ ] 3.3 On first chunk (when `!state.ResponseCreatedSent`):
  - Emit `response.created` event:
    ```json
    {
      "type": "response.created",
      "response": { "id": "<id>", "object": "response", "status": "in_progress", "model": "<model>", "output": [] }
    }
    ```
  - Emit `response.output_item.added` event:
    ```json
    {
      "type": "response.output_item.added",
      "output_index": 0,
      "item": { "type": "message", "id": "<id>", "status": "in_progress", "role": "assistant", "content": [] }
    }
    ```
  - Set `state.ResponseCreatedSent = true`, `state.OutputItemAddedSent = true`.

- [ ] 3.4 For each text delta in `choices[0].delta.content`:
  - Emit `response.output_text.delta`:
    ```json
    { "type": "response.output_text.delta", "output_index": 0, "content_index": 0, "delta": "<text>" }
    ```

- [ ] 3.5 For tool call deltas in `choices[0].delta.tool_calls`:
  - On new tool call (has `id` field): record in `state.ToolCalls`.
  - On argument fragment: emit `response.function_call_arguments.delta`:
    ```json
    { "type": "response.function_call_arguments.delta", "output_index": <N>, "call_id": "<call_id>", "delta": "<args_fragment>" }
    ```

- [ ] 3.6 On `finish_reason` present (terminal chunk):
  - Capture usage from `chunk["usage"]` if present.
  - Emit `response.output_text.done` (if text was streamed):
    ```json
    { "type": "response.output_text.done", "output_index": 0, "content_index": 0, "text": "" }
    ```
  - Emit `response.output_item.done`:
    ```json
    { "type": "response.output_item.done", "output_index": 0, "item": { "type": "message", "id": "<id>", "status": "completed", "role": "assistant", "content": [{ "type": "output_text", "text": "", "annotations": [] }] } }
    ```
  - Emit `response.completed`:
    ```json
    {
      "type": "response.completed",
      "response": {
        "id": "<id>", "object": "response", "status": "completed", "model": "<model>",
        "output": [{ "type": "message", "id": "<id>", "status": "completed", "role": "assistant", "content": [{ "type": "output_text", "text": "", "annotations": [] }] }],
        "usage": { "input_tokens": N, "output_tokens": N, "total_tokens": N }
      }
    }
    ```

- [ ] 3.7 Add helper `public static string FormatSseEvent(string eventName, JsonObject data)` returning `"event: {eventName}\ndata: {json}\n\n"`.

> **Dev Note:** The `text` field in `response.output_text.done` and `response.output_item.done.item.content[0].text` should be empty string `""` — Codex CLI assembles the full text from the deltas and does not require the done events to carry the full accumulated text. This matches the pattern used by LangWatch and OmniRoute's reference implementations.

### Task 4 — `HandleResponsesAsync` in `ProxyService.cs` (AC: 1, 6, 7, 9)

**File:** `Services/ProxyService.cs` (modify) + `Services/IProxyService.cs` (modify)

- [ ] 4.1 Add to `IProxyService.cs`:
  ```csharp
  Task HandleResponsesAsync(HttpContext ctx);
  ```
- [ ] 4.2 Implement `HandleResponsesAsync` in `ProxyService.cs`:
  - Read + parse request body as `JsonNode`. Return 400 with Responses error shape if missing `model`.
  - Check for missing `model` → return 400 `{ "object": "response", "status": "failed", "error": { "code": "invalid_request_error", "message": "model must be specified" } }`.
  - Call `ResponsesRequestTranslator.ToOpenAI(reqNode)` to get `openaiReq`.
  - Set `RequestedModel = openaiReq["model"]?.ToString()`, `IsStream = req["stream"]?.GetValue<bool>() ?? false`.
  - Build a `ResponsesStreamState` if streaming.
  - Set `OnStreamChunkAsync` callback: parse each Chat Completions SSE chunk, call `ResponsesStreamTranslator.Translate(chunk, ref state)`, write each `(eventName, data)` pair as SSE via `FormatSseEvent`.
  - Forward `anthropic-version` / `anthropic-beta` stripping follows same guard as Anthropic path (already in `ExecuteSingleProviderAsync`).
  - For non-streaming: call `ExecuteCompletionAsync`, then call `ResponsesResponseTranslator.ToResponses(respNode, model)`, write JSON.
  - For errors: call `ResponsesResponseTranslator.BuildError(statusCode, message)`, write JSON.
  - Set `Content-Type: application/json` (non-streaming) or `text/event-stream` (streaming).

## Dev Notes

### Architecture Pattern Reference

This story follows the **exact same pattern** as `Story 8.6` (Anthropic Messages translation). The three files to create mirror:

| New file | Mirrors | Location |
|---|---|---|
| `ResponsesRequestTranslator.cs` | `AnthropicRequestTranslator.cs` | `Services/Translation/` |
| `ResponsesResponseTranslator.cs` | `AnthropicResponseTranslator.cs` | `Services/Translation/` |
| `ResponsesStreamTranslator.cs` | `AnthropicStreamTranslator.cs` | `Services/Translation/` |

And `HandleResponsesAsync` in `ProxyService.cs` mirrors `HandleAnthropicMessagesAsync` (lines ~115–270 of `Services/ProxyService.cs`).

### Protocol Mapping Reference

**Request (Responses → Chat Completions):**

```
Responses field              → Chat Completions field
─────────────────────────────────────────────────────
instructions (string)        → messages[0] { role: "system", content: instructions }
input (string)               → messages[-1] { role: "user", content: input }
input[].type="message"       → messages[] { role, content }
  .content[].type="input_text"  → content[].text  (or flatten to string if single part)
input[].type="function_call_output"  → { role:"tool", tool_call_id:call_id, content:output }
max_output_tokens            → max_tokens
temperature                  → temperature (unchanged)
tools[].type="function"      → tools[].type="function" (same schema — passthrough)
tool_choice                  → tool_choice (passthrough)
stream                       → stream
previous_response_id         → (silently drop)
store                        → (silently drop)
```

**Response (Chat Completions → Responses):**

```
Chat Completions             → Responses
─────────────────────────────────────────────────────────────────
choices[0].message.content   → output[0].content[0].text
  (type="output_text" wrapper)
choices[0].message.tool_calls[] → output[N].{ type:"function_call", id, call_id, name, arguments, status:"completed" }
usage.prompt_tokens          → usage.input_tokens
usage.completion_tokens      → usage.output_tokens
usage.total_tokens           → usage.total_tokens
id (chatcmpl-xxx)            → id (strip "chatcmpl-" prefix, prepend "resp_")
object "chat.completion"     → object "response"
                             + status "completed"
                             + created_at (unix seconds)
                             + model (from request)
                             + error null
                             + incomplete_details null
```

**Streaming SSE sequence (Chat Completions → Responses):**

```
Chat Completions event                Responses API event(s)
─────────────────────────────────────────────────────────────
First chunk (any)              →  response.created
                                  response.output_item.added
delta.content (text fragment)  →  response.output_text.delta
delta.tool_calls (new)         →  response.output_item.added (function_call item)
delta.tool_calls (args frag)   →  response.function_call_arguments.delta
finish_reason present          →  response.output_text.done (if text)
                                  response.output_item.done
                                  response.completed
```

### `AnthropicStreamState` as pattern for `ResponsesStreamState`

`ResponsesStreamState` is simpler than `AnthropicStreamState` — no `ThinkingBlock`, no `NextContentBlockIndex`. Reuse `ToolCallInfo` record unchanged. [Source: Models/Provider.cs line 218–234]

### AOT-safe response writing

Do NOT use `Results.Json(anonymousObj, ...)`. Use:
```csharp
ctx.Response.ContentType = "application/json";
await ctx.Response.WriteAsync(responseNode.ToJsonString(), ct);
```
This is the pattern in `HandleAnthropicMessagesAsync` (~line 251). [Source: Services/ProxyService.cs]

### Codex CLI `config.toml` format (confirmed from OmniRoute wiki)

```toml
model                          = "providerId/modelName"
model_provider                 = "minirouter"
model_reasoning_effort         = "medium"
model_context_window           = 128000
model_auto_compact_token_limit = 100000
model_max_output_tokens        = 32768

[model_providers.minirouter]
name     = "MiniRouter"
base_url = "http://localhost:8080/v1"
env_key  = "MINIROUTER_API_KEY"
wire_api = "responses"
```

`base_url` includes `/v1` — Codex appends `/responses` to form the full path `http://localhost:8080/v1/responses`. [Source: OmniRoute wiki / LangWatch docs]

### CodeRabbit Focus Areas

- **AOT safety:** all response writing via `ctx.Response.WriteAsync(node.ToJsonString())`, not `Results.Json` with anonymous objects
- **SSE event ordering:** `response.created` must be first; `response.completed` must be last; emitting out of order will break Codex CLI's parser

- **Tool call index tracking:** `ToolCallInfo` reuse — ensure `BlockIndex` maps correctly to `output_index` in Responses shape
