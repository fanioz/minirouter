# Story 9.1: Preset Providers from OmniRoute Reference

## Description

MiniRouter currently requires users to manually create each provider by entering ID, name, base URL, API key, and models. The [OmniRoute](docs/reff) reference implementation has a curated **preset provider catalog** — built-in templates users can enable with one click (like `opencode-free`, `openrouter`, `deepseek`, `groq`). This story adds the same preset system to MiniRouter.

Preset providers are **templates only** — enabling a preset creates a regular provider pre-filled from the template. Users can enable the same preset multiple times with different keys (e.g., `deepseek-2`, `deepseek-3`), and MiniRouter's existing round-robin routing rotates across them. Once created, each provider is fully editable and independent of the original template.

## Priority

1 (Must-have feature for onboarding ease)

## Implementation Steps

### 1. Backend data model (`Services/Presets/ProviderPreset.cs`)

Add three classes:
- `ProviderPreset` — the preset template record with fields: `Id`, `Name`, `Category`, `BaseUrl`, `ApiKeyRequired`, `DefaultApiKey`, `ModelsUrl`, `DefaultModels`, `Display`
- `PresetCategory` enum: `Free` (no auth required) | `ApiKey` (requires user key)
- `EnablePresetRequest` — DTO for the POST `/api/presets/{id}/enable` body

The `Display` sub-record includes color hex for badges, text icon (2 letters), website/API key URLs, and a short notice.

### 2. Hardcoded catalog (`Services/Presets/PresetCatalog.cs`)

Static array of 4 initial presets mirroring OmniRoute’s registry pattern:

| ID | Category | Base URL | Default Key | Models |
|---|---|---|---|---|
| `opencode-free` | Free | `https://opencode.ai/zen` | `public` | Dynamic fetch via `/zen/v1/models` (filter only free: `-free` suffix + `big-pickle`) |
| `openrouter` | ApiKey | `https://openrouter.ai/api` | none | Dynamic fetch (filter only zero-cost models: `pricing.prompt==0 && pricing.completion==0`) |
| `deepseek` | ApiKey | `https://api.deepseek.com` | none | Static list: `deepseek-chat`, `deepseek-reasoner` |
| `groq` | ApiKey | `https://api.groq.com/openai` | none | Static list: `llama-3.3-70b-versatile`, `openai/gpt-oss-120b`, etc. |

OAuth category skipped (no OAuth flow in MiniRouter).

### 3. Service layer (`Services/Presets/IPresetService.cs` / `PresetService.cs`)

Implement interface:
- `GetAllAsync()` → returns all presets plus `connectedCount` (number of providers created from each preset)
- `EnablePresetAsync(id, apiKey?, name?)`:
  - Validate connection first (call upstream test endpoint with Bearer token, 5s timeout)
  - If duplicate preset ID exists, auto-generate suffix: `deepseek-2`, `deepseek-3`, etc.
  - Create provider via existing `IProviderService.CreateProviderAsync()`, setting `PresetId` field
- `GetSuggestedModelsAsync(id)` → fetch models from `ModelsUrl`, apply filter, cache for 10 min

### 4. Database schema (`Models/Provider.cs`)

Add optional field `string? PresetId = null` to `Provider`, `CreateProviderDto`, `UpdateProviderDto`, and `MaskedProvider`. Backward-compatible: old `providers.json` rows deserialize with null.

### 5. API endpoints (`Program.cs`)

Register `IPresetService` as singleton and add 3 new routes:
```csharp
app.MapGet("/api/presets", async (IPresetService s) => /* return catalog */);
app.MapPost("/api/presets/{id}/enable", async (...)); // 201 or 400/404/409
app.MapGet("/api/presets/{id}/models", async (...)); // suggested free models
```

### 6. Frontend: Presets catalog (`frontend/src/Presets.svelte`)

New tab component:
- Two tabs: "Free" and "API Key"
- Card grid showing preset name, color badge (preset hex), category tag, note about free tier
- Actions:
  - **Free presets**: One-click "Enable" (uses default API key)
  - **API key presets**: Opens modal with password input + optional name; validates before enabling
- Post-enable dialog: show suggested free models as chips; user can "Apply these N models" (PUTs provider’s `models[]` array) or "Skip"
- Reuse bits-ui components from `$lib/components/ui/` (Dialog, Input, Button, Card, Badge)

### 7. Frontend enhancements (`App.svelte` + `Providers.svelte`)

- Add "Presets" tab entry between `providers` and `models` tabs
- In `Providers.svelte` table, show `<Badge>Preset</Badge>` next to provider ID if it has `presetId != null`
- Edit modal shows warning: "Created from the *DeepSeek* preset — edits affect only this provider; the preset template is unchanged."
