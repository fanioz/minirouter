# Story 4.2: Playground Model Selector — Show Provider Context

## Status

Draft

## Story

As a developer using the MiniRouter Playground,
I want to see which provider each model belongs to in the model selector,
So that I can make an informed choice when multiple providers serve the same model name.

## Background

Story 4.1 built the Playground chatbox. The model selector is populated from `GET /models` (the aggregated live-discovery endpoint), which already returns `providerId` and `providerName` alongside each model. However, the current dropdown label is built from **only** `m.id`:

```js
// Current code — Playground.svelte onMount
models.push({ value, label: m.id });  // ← providerName is silently discarded
```

This means a user who has two providers both serving `gpt-4o` sees two **identical** option labels `gpt-4o` in the dropdown — with no way to distinguish between them. Even in the single-provider case, the user can't tell whether `claude-opus-4-5` came from `anthropic-direct` or `openrouter`.

The routing value (`value` field) is already `providerId/modelId` — the correct routing is happening; the display just doesn't reflect it.

**The fix is frontend-only.** No backend changes are needed — `providerName` is already in the `/models` response.

---

## Acceptance Criteria

1. Each option in the model dropdown shows both the model name and its provider — format: `model-name — Provider Name` (em-dash separator, e.g. `gpt-4o — OpenAI Primary`).
2. When two or more providers offer the same model name, both entries are shown as distinct options with distinct labels (e.g. `gpt-4o — OpenAI Primary` and `gpt-4o — OpenRouter`).
3. The `auto (round-robin)` option label is unchanged.
4. The routing `value` sent to `/v1/chat/completions` as the `model` field remains `providerId/modelId` (no change to request behavior).
5. Models are **grouped by provider** in the dropdown using `<optgroup label="Provider Name">` elements — one group per provider, in the order returned by `/models`.
6. If a provider's model list failed to load (`provider.error` is non-null), a disabled `<optgroup>` is rendered for that provider with the error message as a single disabled option: `⚠ Could not load models`.
7. The circuit status of each model is shown inline in the option label: a green dot `●` for `healthy`, amber `●` for `degraded`, red `●` for `open` (circuit breaker tripped). Format: `● gpt-4o` (dot prefix, colored via CSS class or inline style).
8. The dropdown's selected display (closed state) shows the full `model — Provider Name` format, not just the model ID.
9. `npm run build` clean (no TypeScript/Svelte errors).

## Tasks / Subtasks

### Task 1 — Update `availableModels` shape in `Playground.svelte` (AC: 1, 2, 4, 7)

**File:** `frontend/src/Playground.svelte`

The `availableModels` array currently holds `{ value, label }` flat entries. Extend it to group entries by provider.

- [ ] 1.1 Change the `availableModels` state type from `{ value, label }[]` to `ProviderGroup[]`:
  ```typescript
  type ModelOption = {
    value: string;        // "providerId/modelId" — unchanged
    label: string;        // "model-name — Provider Name"
    modelId: string;      // bare model id
    circuitStatus: string; // "healthy" | "degraded" | "open"
  };

  type ProviderGroup = {
    providerId: string;
    providerName: string;
    error: string | null;
    models: ModelOption[];
  };
  ```

- [ ] 1.2 In `onMount`, replace the flat loop with a per-provider structure:
  ```js
  const groups = [];
  for (const provider of data) {
    const group = {
      providerId: provider.providerId,
      providerName: provider.providerName,
      error: provider.error ?? null,
      models: []
    };

    if (provider.models && Array.isArray(provider.models)) {
      if (provider.models.length === 0) hasWildcard = true;
      for (const m of provider.models) {
        if (!m.id) continue;
        const value = `${provider.providerId}/${m.id}`;
        group.models.push({
          value,
          label: `${m.id} — ${provider.providerName}`,
          modelId: m.id,
          circuitStatus: m.circuitStatus ?? 'healthy'
        });
      }
    } else {
      hasWildcard = true;
    }

    groups.push(group);
  }
  availableModels = groups;
  ```

- [ ] 1.3 Update `selectedModel` default selection — still picks `groups[0]?.models[0]?.value`:
  ```js
  const firstModel = groups.flatMap(g => g.models)[0];
  if (firstModel && !selectedModel) selectedModel = firstModel.value;
  ```

### Task 2 — Rebuild dropdown template with `<optgroup>` (AC: 1, 2, 3, 5, 6, 7, 8)

**File:** `frontend/src/Playground.svelte` (template section)

- [ ] 2.1 Replace the flat `{#each availableModels as model}` loop with a grouped template:
  ```svelte
  <select id="model-select" bind:value={selectedModel} ...>
    {#if availableModels.length === 0}
      <option value="auto">auto (round-robin)</option>
    {:else}

      {/if}

          {:else}
            {#each group.models as model}
              <option value={model.value}>
                {circuitDot(model.circuitStatus)}{model.modelId} — {group.providerName}
              </option>
            {/each}
          {/if}
        </optgroup>
      {/each}
    {/if}
  </select>
  ```

- [ ] 2.2 Add `circuitDot` helper function:
  ```js
  function circuitDot(status) {
    if (status === 'open')     return '🔴 ';
    if (status === 'degraded') return '🟡 ';
    return '🟢 ';   // healthy or unknown
  }
  ```
  > **Dev Note:** Unicode colored circles render consistently across OS/browser in `<option>` text — no CSS is needed. This avoids the `<option>` styling limitation (browsers don't render HTML inside `<option>` elements).

## Dev Notes

### The Data is Already There

The `/models` response already contains everything needed:

```json
[
  {
    "providerId": "openai-primary",
    "providerName": "OpenAI Primary",
    "models": [
      { "id": "gpt-4o",      "circuitStatus": "healthy" },
      { "id": "gpt-4o-mini", "circuitStatus": "healthy" }
    ],
    "error": null
  },
  {
    "providerId": "openrouter",
    "providerName": "OpenRouter",
    "models": [
      { "id": "gpt-4o", "circuitStatus": "degraded" }
    ],
    "error": null
  }
]
```

The change is entirely in how `Playground.svelte` processes and renders the response — no backend changes needed.

### `<optgroup>` Behaviour

`<optgroup label="Provider Name">` is supported in all modern browsers. The browser renders the group label as a non-selectable separator above the grouped options. The `label` attribute is visible to the user in both the open and closed dropdown states (in the open state).

### Routing Value Unchanged

The `value` attribute of each `<option>` stays `providerId/modelId`. This is what gets sent as `model` in the `/v1/chat/completions` request body — no behavior change.

### `circuitDot` Emoji Notes

Unicode circle emojis (🟢 🟡 🔴) render in native `<option>` text in Chrome, Firefox, Safari, and Edge on macOS and Windows. This is the only cross-browser-safe way to add color indicators inside `<option>` elements (CSS `color` on `<option>` is not supported in most browsers).

Fallback if emoji causes issues: use ASCII `[OK]`, `[WARN]`, `[DOWN]` prefix strings.
