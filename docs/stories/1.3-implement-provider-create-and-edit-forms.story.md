# Story 1.3: Implement Provider Create and Edit Forms

## Status
Ready for Review

## Story
**As an** Administrator,
**I want** to add new providers and edit existing ones via a form,
**so that** I don't have to manually edit `providers.json`.

## Acceptance Criteria
1. A form is provided to input `Id`, `BaseUrl`, `ApiKey`, and `Models`.
2. Submitting the form makes a `POST /providers` or `PUT /providers/{id}` request.
3. Form validation prevents submission with missing required fields.
4. The list view is updated after a successful save.

## Dev Notes
- **Previous Story Insights**: Provider list view and API structure are in place from Story 1.2.
- **Data Models**: Provider (`Id`, `BaseUrl`, `ApiKey`, `Models`).
- **API Specifications**: The API endpoints are `POST /providers` and `PUT /providers/{id}`.
- **Component Specifications**: Use React, Tailwind CSS, and Shadcn UI (Form, Input, Dialog). React Hook Form is recommended for validation. [Source: architecture/component-architecture.md]
- **Flow Details**: "Click Add/Edit -> Open Form Modal -> User Fills Data -> Submit Form -> Validation Pass? -> POST/PUT /providers -> API Success? -> Show Success Toast & Refresh List". [Source: frontend/user-flows.md]
- **File Locations**: Create new components in `frontend/src/components/` context.
- **Testing Requirements**:
  - Integration Verification IV1: Add a provider via UI and verify `providers.json` is successfully updated on disk.
  - Integration Verification IV2: Restart the backend and verify the newly added provider persists.

### Testing
