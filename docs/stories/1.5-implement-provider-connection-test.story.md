# Story 1.5: Implement Provider Connection Test

## Status
Completed

## Story
**As an** Administrator,
**I want** to test the connection to a provider when I add or edit it,
**so that** I know the URL and API key are valid before saving.

## Acceptance Criteria
1. The Provider Form (Add/Edit) includes a "Test Connection" button.
2. Clicking the button sends a test request to the provider using the currently inputted `BaseUrl` and `ApiKey`.
3. A loading state is shown during the test.
4. A visual indicator (toast or inline message) displays success if the connection is valid, or the error message if it fails.
5. The form can still be saved even if the test fails (optional, depending on strictness, but standard is to allow save).

## Dev Notes
- **CORS Warning**: Testing a provider URL directly from the browser (Svelte frontend) will likely result in CORS errors since most LLM APIs do not allow browser origins. The backend should ideally provide a `/api/providers/test` endpoint that accepts `{ baseUrl, apiKey }` and performs the request server-side to avoid CORS.
- If the backend endpoint does not exist yet, this story includes adding that simple proxy test endpoint to the backend (e.g. hitting the `/models` path of the given base URL).

### Testing
- Enter valid credentials and ensure "Test Connection" shows success.
- Enter invalid credentials (wrong URL or API key) and ensure it shows an error.
- Verify CORS is not an issue (use backend proxy test endpoint).
