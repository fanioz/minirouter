# Story 8.3: Error Classification and Exponential Backoff

## Description

MiniRouter's circuit breaker applies a **fixed 30-second cooldown** to every failure,
regardless of what the provider actually said. A provider returning `Retry-After: 300` is
retried roughly 10× too early — burning quota, re-tripping the breaker, and in the worst case
escalating a soft rate-limit into a hard ban.

This is the highest return-per-hour item in Epic 8. The reference implementation
(`docs/reff/open-sse/config/errorConfig.js`) is ~80 lines of declarative rules that translate
almost directly to C#.

The story also fixes two circuit-breaker defects found during the gap analysis:

**Defect A — half-open is not representable.** `GetCircuitStatus`
(`Services/ProviderService.cs:300`) returns only `"healthy"` or `"open ({n}s)"`. The explicit
routing path rejects anything not exactly `"healthy"` (`Services/ProxyService.cs:143`), so a
provider whose cooldown has expired is still refused on that path.

**Defect B — no probe gate.** `IsProviderEligibleForRouting`
(`Services/ProviderService.cs:281-298`) returns eligible once `elapsed >= cooldown`, but
`ConsecutiveFailures` is left at or above the threshold. One further failure re-trips
immediately. The inline comment calls this half-open; there is no probe-count or single-trial
gate, so the behavior does not match the name.

## Priority

1 (Wave 1 — highest resilience return)

## Implementation Steps

### 1. Port the error classification rules

Create `Services/ErrorClassifier.cs` mirroring `docs/reff/open-sse/config/errorConfig.js:59`.
Rules are evaluated **text-first, then status** — order within each group is priority:

| Match | Kind | Cooldown |
|---|---|---|
| text `no credentials` | fixed | 2 min |
| text `request not allowed` | fixed | 5 s |
| text `improperly formed request` | fixed | 2 min |
| text `rate limit` | backoff | exponential |
| text `too many requests` | backoff | exponential |
| text `quota exceeded` | backoff | exponential |
| text `capacity` | backoff | exponential |
| text `overloaded` | backoff | exponential |
| status 401 / 402 / 403 / 404 | fixed | 2 min |
| status 429 | backoff | exponential |
| unmatched | fixed | 30 s (transient default) |

Text matching is case-insensitive substring. Keep the table as a static array of records —
declarative data, not a `switch`, so adding a rule stays a one-line change.

### 2. Add exponential backoff

Per `BACKOFF_CONFIG` in the reference: `base 2000ms × 2^(level-1)`, capped at 5 min, max level
15.

Add `BackoffLevel` to the `CircuitState` class (`Services/ProviderService.cs:45`). Increment on
each backoff-classified failure; **reset to 0 on success**. Fixed-cooldown failures do not
touch the level.

### 3. Honor provider-reported reset times

A provider-supplied reset time **overrides** computed backoff. Parse, in priority order:

1. `Retry-After` response header — both the delta-seconds and HTTP-date forms
2. `resets_at` / `usage_limit_reached.resets_at` in the error body, where present

Cap the honored value at **30 minutes** (`MAX_RATE_LIMIT_COOLDOWN_MS` in the reference).
Uncapped values are a hazard — Codex `resets_at` can be 5-6 hours, which would silently remove
a provider from rotation for most of a working day.

### 4. Fix defect A — representable half-open

Introduce an explicit tri-state rather than string comparison:

```csharp
public enum CircuitStatus { Healthy, HalfOpen, Open }
```

`GetCircuitStatus` returns the enum; keep a string projection for the `/models` API response so
the dashboard contract does not break. Update `Services/ProxyService.cs:143` to accept both
`Healthy` and `HalfOpen`.

### 5. Fix defect B — real probe gate

On cooldown expiry, allow exactly **one** in-flight probe request through per state key.

- Probe succeeds → reset `ConsecutiveFailures` and `BackoffLevel` to 0, status `Healthy`
- Probe fails → re-trip with the next backoff level, status `Open`
- While a probe is in flight, other requests for that key are **not** eligible

This requires a probe-in-flight flag on `CircuitState`, set and cleared under the existing
per-state `lock`.

### 6. Replace Console.WriteLine with ILogger

Circuit trip and recovery events currently go to `Console.WriteLine`
(`Services/ProviderService.cs`), bypassing log-level configuration. Move to `ILogger`. Keep
messages structured — provider id, model, classification, cooldown applied, backoff level.

## Acceptance Criteria

- [x] A 429 with `Retry-After: 300` defers that provider/model for 300 s, not 30 s
- [x] A `Retry-After` of 6 hours is capped to 30 minutes
- [x] Repeated rate-limit failures produce 2 s → 4 s → 8 s → 16 s cooldowns, capped at 5 min
- [x] `BackoffLevel` resets to 0 after a successful request
- [x] A 401 receives a 2 min fixed cooldown and does **not** increment `BackoffLevel`
- [x] An unmatched 500 receives the 30 s transient default
- [x] Text rules take precedence over status rules (a 500 body containing "overloaded" backs off)
- [x] Explicit routing accepts a `HalfOpen` provider (defect A closed)
- [x] Exactly one probe passes on cooldown expiry; a failed probe re-trips without a second probe (defect B closed)
- [x] Trip/recovery events emit via `ILogger`, not `Console.WriteLine`
- [x] `/models` still returns the string circuit status the dashboard expects

## Required Tests (QA)

This story carries the epic's circuit-breaker coverage — currently the highest-risk untested
logic in the codebase.

- Classification: one test per rule row, including text-beats-status precedence
- Backoff: level progression, 5 min cap, reset-on-success, max level 15
- `Retry-After`: delta-seconds form, HTTP-date form, 30 min cap, absent header
- Probe gate: single probe admitted, concurrent requests refused during probe, success closes,
  failure re-trips at the next level
- Trip threshold and cooldown expiry (no existing coverage)
- Regression: comma-separated fallback (Story 7.1) still falls back on 5xx and 429, and still
  does not fall back on 400
